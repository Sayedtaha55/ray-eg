## 2025-06-27 - [Product visibility lookups and Zero-DB Cache Hit pattern]
**Learning:** In the current architecture, visibility checks for products (hiding products linked to image maps or hotspots) were happening after cache retrieval. This meant every cache hit still triggered multiple database lookups to verify visibility, negating much of the cache benefit. Parallelizing lookups in `getById` reduces total latency, but implementing the "Zero-DB Cache Hit" pattern (filtering visibility upstream and caching the final result) is critical for performance at scale.
**Action:** When implementing caching for data that requires additional filtering or visibility rules, apply all filters before caching. Ensure surgical cache invalidation is implemented in services that can modify the visibility state (e.g., `ShopImageMapService`).

## 2026-07-24 - [Handling Pre-Existing Schema Validation Errors in NestJS + Prisma Environment]
**Learning:** The PostgreSQL schema file `prisma/schema.prisma` had validation mapping collisions and relation definition bugs that completely block Prisma client generation and compilation checks on clean installation. While these must be resolved locally to successfully build/run tests and typechecks, any changes to `prisma/schema.prisma` are strictly out-of-scope for performance optimizations and must be fully reverted via git restore before code review or submission to prevent unintended schema modifications.
**Action:** Always document pre-existing schema blockers, resolve them locally to perform verification, and perform a complete `git restore` on schema files before generating the final PR diff.

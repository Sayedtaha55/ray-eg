## 0. اكتشافات مهمة (اتأكدنا منها على بيانات حقيقية) ⚠️

دي حاجتين كانوا بيمنعوا كل صفحات الأقسام إنها تعرض أي حاجة:

1. **`shops.activity` بيخزّن العنوان العربي، مش الـ id الإنجليزي.**
   `apps/business/src/app/signup/page.tsx:286` بيعمل `activity: selectedActivity.title`، وبالتالي
   قاعدة البيانات فيها `'معارض سيارات'` وليس `'carShowroom'`.
   ⇒ أي فلترة بالـ ids الإنجليزي بترجّع صفر. لازم نفلتر بالعناوين العربية (أو نخزّن slug ثابت).

2. **الفلتر في الباك إند كان بيرجّع 500 لكل طلب.**
   `shops.category` نوعه enum في Postgres اسمه `"ShopCategory"`، و`LOWER()` مش معرّفة على الـ enum:
   `ERROR: function lower("ShopCategory") does not exist (SQLSTATE 42883)`.
   ⇒ أي `?shopActivity=` كان بيفشل بالكامل. اتصلح بـ `LOWER(s.category::text)`.

3. **الفلتر بقى يدعم أكتر من قيمة مفصولة بفاصلة** (OR بينهم)، عشان القسم الواحد يجمّع أكتر من نشاط.
   ✅ اتأكدنا: `?shopActivity=RETAIL,معارض سيارات` → رجّع النتايج، و`zzz_nope` → صفر بدون أخطاء.

## 2. نظام الأوضاع (`mode`) — قلب النظام

| mode            | الشرح                                               | مثال الأقسام                                     |
| --------------- | --------------------------------------------------- | ------------------------------------------------ |
| `products`      | منتجات عادية بسعر + سلة                             | سوبر ماركت، ملابس، إلكترونيات، صيدلية            |
| `menu`          | منيو خاص + فلاتر (تصنيف/سعر/حار/بارد)               | مطاعم، كافيهات، مخابز، حلويات                    |
| `booking`       | حجز بموعد (تقويم + وقت)                             | عيادات، دكتور، صالون                             |
| `request_quote` | **من غير سعر نهائي** + "احجز 24 ساعة" بالاسم والرقم | أثاث، تجارة جملة، وكلاء                          |
| `services`      | خدمات + طلب عرض سعر / حجز زيارة                     | خدمات منزلية، خدمات مهنية، مقاولات، صيانة، زراعة |
| `classifieds`   | إعلانات (بيع/شراء/مقايضة)                           | عقارات، سيارات                                   |

### تعريف القسم (TypeScript)

```ts
export type ActivityMode =
  'products' | 'menu' | 'booking' | 'request_quote' | 'services' | 'classifieds';

export type ActivityDef = {
  id: string; // 'restaurant' — يطابق shop.activityId
  label: { ar: string; en: string };
  image: string;
  mode: ActivityMode; // ⭐ الحقل الجديد
  group: string; // 'food_market' | 'health' | ... للتنظيم
  supportsPrice: boolean; // false => أخفي السعر وورّي "اطلب عرض سعر"
  supportsCart: boolean; // false => أخفي السلة وزوّر CTA الحجز
  quoteCta?: { ar: string; en: string }; // نص الزر (مثال: "احجز 24 ساعة")
  ctaKind?: 'booking' | 'quote' | 'call' | 'whatsapp';
  unitLabel?: { ar: string }; // 'ساعة' / 'جلسة' / 'رحلة'
};
```

**مبدأ مهم:** `supportsPrice: false` هو اللي بيمنع عرض السعر — زي ما طلبت في قسم الأثاث.

## 7. Trader-Controls — قرار التاجر في `layoutConfig.commerce` ✅ (مرفوع في `f523c8c7`)

> **القاعدة:** التاجر بيقرر شكل بياعته — والقسم (`mode`) بيبقى **fallback** بس.
> الترتيب في `resolveCommerce()`: **اختيار التاجر** ← بيانات المنتج (فيه سعر ولا لأ) ← وضع القسم.

### 7.1 المخزّن (مفيش migration)

عمود `shops.layoutConfig` (JSONB موجود أصلاً، بيتحدّث من `PUT/PATCH /shops/me`)، وتحته مفتاح `commerce`:

```jsonc
{
  "commerce": {
    "pricing": "priced",          // "priced" = نعرض السعر | "hidden" = "السعر عند الطلب"
    "ordering": "booking24h",     // "cart" | "booking24h" | "appointment" | "contact"
    "bookingWindowHours": 24,     // "رد خلال N ساعة" — مقبول من 1 لـ 72
    "queueEnabled": true          // "كام واحد قدامي" (الطابور)
  },
  "enabledFeatures": { "...": "بيتسجلوا جنبه من غير ما يتقضى عليهم" },
  "posSettings": { "...": "نفس الشي" }
}
```

- **`pricing: hidden`** → مفيش سعر، ولا نسبة خصم، ولا `price` في الـ JSON-LD (عشان ما يتسربش).
- **`ordering`** بيحدّد الـ CTA: `cart` → زر السلة · `booking24h` → "احجز 24 ساعة" · `appointment` → "احجز موعد" · `contact` → مفيش زر (الواتساب/التليفون الموجودين بس).
- قراءة آمنة: أي حقل ناقص أو قيمة غريبة بتتجاهل بدل ما تكسر الصفحة (`readShopCommerce`).

### 7.2 أين يتطبّق

| المكان | الملف |
| --- | --- |
| مصدر القرار | `apps/marketplace-next/src/lib/commerce.ts` |
| زر الإجراء (سلة/حجز/تواصل) | `src/components/CommerceAction.tsx` |
| مودال الحجز + الطابور | `src/components/BookingRequestModal.tsx` |

`useShopCommerce(shopId, shopProp)` بيجيب `layoutConfig` بتاع تاجر المنتج من قائمة `/shops` (الـ API client فيه cache 30 ثانية + dedup، فمئات البطاقات بطلب واحد)، مع أفضلية للـ `shop` اللي الصفحة مرّرته بنفسها.

### 7.3 طبقة الكاش — كانت بتاكّل القرار

قرار التاجر كان بيتغيّر، بس الواجهة مش بتتغيّر فورًا. اتقبض على **طبقتين** في نفس الوقت:

1. **Next.js Data Cache:** `getShops()` كان بيرجع `revalidate: 300` من غير سبب. أي تعديل في الداشبورد يفضل محفوظ **5 دقايق** في الماركت.
   - الحل: `getShops(take, fresh)` — و`fresh: true` بيلغي الكاش، وصفحة المنتج بتستخدمه عشان تشوف آخر قرار فورًا.
2. **Go public-shop cache:** `ListPublic` بيخزّن `/shops` 30 ثانية، و**أي تعديل على المتجر مكانش بيبطّله** — فحتى لو الـ Next اتحدّث، الداتابيز كانت راجعة بالقديم.
   - الحل: `invalidatePublicList()` بتمسح `shops:public:*` بعد `CreateShop` / `UpdateMyShop` / `UpdateAdminShop` / `UpdateStatus`.

> بعد الإصلاحين: تعديل واحد من الداشبورد → بيظهر في `/shops` في نفس اللحظة (اتأكدنا بمقارنة `/shops/me` مع `/shops` بعد كل `PATCH`).

### 7.4 تسريب السعر في أول HTML

صفحة المنتج كانت بتقول "السعر عند الطلب" الصح، بس **منتجات ذات صلة** في نفس الصفحة كانت بتطبع السعر في أول HTML، وبعد الهيدرايشن بس بتختفي وتبقى "السعر عند الطلب".

- السبب: `ProductCard` بيحلّ قرار التاجر من `useShopCommerce` (fetch في المتصفح)، ومنتجات ذات صلة كانت بتترندر **من غير** `shop` →Decision الافتراضي = سعر ظاهر.
- الإصلاح: صفحة المنتج بتجيب المتجر من `getShops(300, true)` وبتعدّيه للكارت (`<ProductCard shop={shop} />`) — والمنتجات دي كلها لنفس المتجر بالظبط، فمفيش أي طلب إضافي.
- النتيجة المتأكدة من الـ HTML الخام: مفيش `ج.م` ولا رقم السعر في أي مكان، وJSON-LD مفيهوش `price` (الـ `offers` بتحط `price` غير لما السعر متاح).

### 7.5 حدود معروفة (مقصودة دلوقتي)

- **الكروت في الشبكات والسكويلات** (الرئيسية، الأقسام، المفضلة، العروض) بتحلّ قرار التاجر في المتصفح عبر `useShopsIndex` (طلب واحد `/shops?take=300` للتطبيق كله). يعني: **أول HTML** بيطلع بالقرار الافتراضي وبيصحّح بعد ما الواجهة تشتغل (أسفل ثانية). صفحة المنتج والكارت اللي بياخد `shop` مباشرة مابيهاش المشكلة دي.
- حلّها الكامل = تزويد `layoutConfig` من السيرفر لكل صفحة شبكة (index متاجر في السيرفر)، وده تغيير أوسع — يتعمل كخطوة منفصلة لما نرتب أسطح العرض، عشان ميكسرش ISR للصفحات.

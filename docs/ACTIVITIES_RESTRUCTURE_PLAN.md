## 0. اكتشافات مهمة (اتأكدنا منها على بيانات حقيقية) ⚠️

دي حاجتين كانوا بيمنعوا كل صفحات الأقسام إنها تعرض أي حاجة:

1. **`shops.activity` بيخزّن العنوان العربي، مش الـ id الإنجليزي.**
   `apps/business/src/app/signup/page.tsx:286` بيعمل `activity: selectedActivity.title`، وبالتالي
   قاعدة البيانات فيها `'معارض سيارات'` وليس `'carShowroom'`.
   ⇒ أي فلترة بالـ ids الإنجليزي بترجّع صفر. لازم نفلتر بالعناوين العربية (أو نخزّن slug ثابت).

2. **الفلتر في الباك إند كان بيرجّع 500 لكل طلب.**
   `shops.category` نوعه enum في Postgres اسمه `"ShopCategory"`، و`LOWER()` مش معرّفة على الـ enum:
   `ERROR: function lower("ShopCategory") does not exist (SQLSTATE 42883)`.
   ⇒ أي `?shopActivity=` كان بيفشل بالكامل. اتصلح بـ `LOWER(s.category::text)`.

3. **الفلتر بقى يدعم أكتر من قيمة مفصولة بفاصلة** (OR بينهم)، عشان القسم الواحد يجمّع أكتر من نشاط.
   ✅ اتأكدنا: `?shopActivity=RETAIL,معارض سيارات` → رجّع النتايج، و`zzz_nope` → صفر بدون أخطاء.

## 1. الفكرة العامة

الحالي: كل الأقسام **نسخة واحدة** من نفس الصفحة — `ProductCard` موحّد + سعر + زر "أضف للسلة".

المطلوب: كل قسم له **وضع سلوكي مختلف** (`mode`) يتحكم في شكل الصفحة والبطاقات والزر والفلاتر.

العمود الفقري للتعديل هو **ملف واحد**:
`apps/marketplace-next/src/lib/activity-catalog.ts` (جديد — المصدر الوحيد للحقيقة)

بكده لما نضيف قسم جديد، بنزوّد سطر واحد في الكاتالوج، والباقي بيشتغل لوحده.

## 2. نظام الأوضاع (`mode`) — قلب النظام

| mode            | الشرح                                               | مثال الأقسام                                     |
| --------------- | --------------------------------------------------- | ------------------------------------------------ |
| `products`      | منتجات عادية بسعر + سلة                             | سوبر ماركت، ملابس، إلكترونيات، صيدلية            |
| `menu`          | منيو خاص + فلاتر (تصنيف/سعر/حار/بارد)               | مطاعم، كافيهات، مخابز، حلويات                    |
| `booking`       | حجز بموعد (تقويم + وقت)                             | عيادات، دكتور، صالون                             |
| `request_quote` | **من غير سعر نهائي** + "احجز 24 ساعة" بالاسم والرقم | أثاث، تجارة جملة، وكلاء                          |
| `services`      | خدمات + طلب عرض سعر / حجز زيارة                     | خدمات منزلية، خدمات مهنية، مقاولات، صيانة، زراعة |
| `classifieds`   | إعلانات (بيع/شراء/مقايضة)                           | عقارات، سيارات                                   |

### تعريف القسم (TypeScript)

```ts
export type ActivityMode =
  'products' | 'menu' | 'booking' | 'request_quote' | 'services' | 'classifieds';

export type ActivityDef = {
  id: string; // 'restaurant' — يطابق shop.activityId
  label: { ar: string; en: string };
  image: string;
  mode: ActivityMode; // ⭐ الحقل الجديد
  group: string; // 'food_market' | 'health' | ... للتنظيم
  supportsPrice: boolean; // false => أخفي السعر وورّي "اطلب عرض سعر"
  supportsCart: boolean; // false => أخفي السلة وزوّر CTA الحجز
  quoteCta?: { ar: string; en: string }; // نص الزر (مثال: "احجز 24 ساعة")
  ctaKind?: 'booking' | 'quote' | 'call' | 'whatsapp';
  unitLabel?: { ar: string }; // 'ساعة' / 'جلسة' / 'رحلة'
};
```

**مبدأ مهم:** `supportsPrice: false` هو اللي بيمنع عرض السعر — زي ما طلبت في قسم الأثاث.

### 🟡 المرحلة 1 — الصفحة الرئيسية ودليل الأقسام

1. إعادة بناء `DalilClient`: عرض الأقسام كـ**grid** (أيقونة + عنوان + وصف مختصر) بدل قائمة نشاط واحدة.
2. الصفحة الرئيسية: قسم "تصفح حسب النشاط" بشكل cards كبيرة وواضحة (زي الصورة المرفقة).
3. روابط الأقسام تروح لـ`/activity/[id]`.

**القبول:** الأقسام ظاهرة كنظرة (categories) مش كنشاط مختلط.

### 🟠 المرحلة 2 — محرك العرض الموحّد

1. مكوّن `ActivityShell` ياخد `ActivityDef` ويبني الـ layout حسب الـ mode.
2. مكوّنات البطاقة حسب الوضع:
   - `ProductCard` (موجود) — للأقسام اللي فيها سلة
   - `MenuCard` — للمطاعم (صورة كبيرة + اسم + سعر + hint للإضافات)
   - `BookingCard` — للعيادات (اسم + تخصص + "احجز موعد")
   - `QuoteCard` — للأثاث (من غير سعر + "احجز 24 ساعة")
3. **المنتج بدون سعر**: `ProductCard` يستقبل `showPrice={false}` → يخفي السعر ويطلع CTA.
4. CTA الحجز يفتح modal بسيط: الاسم + التليفون + (اختياري وقت للحجوزات).

**القبول:** كل قسم بيشتغل بـ mode بتاعه.

### 🔵 المرحلة 3 — المطاعم (أولوية عالية)

1. **منيو خاص لكل مطعم**: صفحة المطعم `/shop/[slug]` لو mode بتاعه `menu` تعرض:
   - كاتيجورات المنيو (أكل/مشروبات/حلويات)
   - فلاتر: بحث + سعر + حار/بارد
   - items كـ cards كبيرة بصورة واحدة + addons
2. **الشكل التصميمي الجديد** (مش الشكل التقليدي اللي في التطبيقات):
   - صورة كبيرة على اليمين
   - اسم المطعم + نوع الـ cuisine + التقييم
   - CTA واضح واحد: "اطلب دليفري" (مش زر + صغير)
   - Cards بعرض الشاشة
3. السلة بتقبل الإضافات (addons) من صفحة المطعم.

**القبول:** كل مطعم بيبني منيو خاص بيه (مش generic grid).

### 🟣 المرحلة 4 — الأقسام من غير سعر + الحجوزات

1. `request_quote`: صفحة القسم (أثاث) — cards من غير سعر + "احجز 24 ساعة".
2. Modal الحجز: الاسم + التليفون + ملاحظة → POST endpoint جديد `/bookings/quote`.
3. `booking` (عيادات): تقويم + اختيار وقت → POST `/bookings/appointment`.
4. **Backend**: جدول/endpoint جديد للـ bookings (اقتراح: reuse pattern بتاع `map-listings`).

**القبول:** الحجز بيوصل للتاجر وبيتسجل في الداشبورد.

### 🟤 المرحلة 5 — الخريطة (نهاية المشروع)

1. الخريطة في الماركت **بألوان المنصة الثابتة** (سماوي/غامق) — **مفيش تخصيص ألوان للتجار في الماركت**.
2. موقع التاجر في `/map` (دليل المواقع) بيبقى قابل للتخصيص بالكامل من التاجر.
3. يعني: **مكانين مختلفين** — `/map` (دليل، قابل للتخصيص) و `/activity/*` (أقسام، ألوان ثابتة).

**ملاحظة:** زي ما انت قلت "في شغل كبير لسه هنعملوه هناك" — نأجلها لآخر المشروع.
